
Segundo Pressman (2021), a UML (do inglês, _Unified Modeling Language_) fornece uma maneira de descrever uma solução para um problema a partir de múltiplas perspectivas. Analise as afirmações sobre diferentes diagramas UML a seguir.  

I. Diagramas de atividade podem ser descritos como uma forma de representar como o sistema reage a eventos externos.  
II. Diagramas de Caso de Uso podem não ser suficientes para modelar situações que exigem muitos detalhes ou maior precisão.  
III. Os diagramas de sequência podem ser usados para modelagem comportamental e também podem ser usados para mostrar como os eventos provocam transições de objeto para objeto.  
IV. Uma seta tracejada em um diagrama de componentes indica uma comunicação assíncrona entre componentes.

A) Apenas as afirmativas I e II são verdadeiras.
B) Apenas as afirmativas II e III são verdadeiras
C) Apenas as afirmativas III e IV são verdadeiras.
D) Apenas as afirmativas I, II e IV são verdadeiras.
E) Apenas as afirmativas I, III e IV são verdadeiras.

>[!success] Alternativa correta:  B
>Apenas as afirmativas II e III são verdadeiras


**Incorreta**
I. Diagramas de atividades podem ser descritos como uma forma de representar como o sistema reage a eventos externos.

- **Onde está pegadinha**: O diagrama que foca em representar como um sistema (ou objeto) **reage a eventos externos** é o **Diagrama de Máquina de Estados**(ou Diagrama de Estados).

- O **Diagrama de Atividades**, por outro lado, foca no fluxo de controle ou fluxo de dados de uma atividade para outra(como um fluxograma avançado de um processo ou algoritmo)

**Correta**
II. Diagrama de Caso de Uso podem não ser suficientes para modelar situações que exigem muitos detalhes ou maior precisão

- **Por que está correto**: Casos de uso oferecem uma visão de "helicóptero" do sistema. Eles mostram o que o sistema faz e quem interage com ele (Atores), mas são péssimos para mostrar como isso é feiro no nível algorítmico ou estrutural. Para precisão, precisamos descer o nível com diagrama de classe, sequência ou descrições textuais detalhadas.

**Correta**
III. Os diagramas de sequência podem ser usados para modelagem comportamental e também pode ser usado para mostrar como os eventos provocam transições de objeto para objeto.

- O Diagrama de Sequência é o rei da modelagem comportamental baseada no tempo. Os "eventos" mencionados aqui são as **mensagens**(chamadas de métodos, retornos) trocadas entre os diferentes objetos do tempo, provocando as transições no fluxo de execução do cenário

**Incorreta**
IV. Uma seta tracejada em um diagrama de componentes indica uma comunicação assíncrona entre componentes

- Um diagrama de componentes é **estrutural**. Um seta tracejada nesse diagrama indica uma relação de **Dependência**(ex: o Componente A precisa da interface do componente B para compilar ou funcionar). **Comunicação assíncrona** é um conceito **comportamental**(tempo de execução), que é representado primariamente do **Diagrama de Sequência**(usando uma seta de linha contínua com a ponta aberta).

Sempre faça esse filtro:

1. **Reação a Eventos e Mudança de Status** = Diagrama de Estados
2. **Fluxo de Trabalho / Algoritmo** = Diagrama de Atividades
3. **Troca de Mensagens no Tempo** =  Diagrama de Sequência
4. **Setas Tracejadas em Diagrama Estruturais**(Componentes,Classes,Casos de Uso) = **Dependência**(um elemento precisa do outro)
